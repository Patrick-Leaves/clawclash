## 一、规则正确性（engine/rules_core.js）

- [ ] **CC-RULE-01**【P0·自动】规则 v2.1 §5.3 全部官方示例通过 —— `npm run test:rules`（`test_rules.js`）。
- [ ] **CC-RULE-13**【P0·自动】指南规则向量：落点尾部吃子、横竖双线同吃、20 单步按子数裁定 —— `test/rules-examples.test.js`；不据此替代其它官方示例。
- [ ] **CC-RULE-02**【P0·手动】初始布局：黑 (0,3)(1,3)(2,3)(3,3)(0,2)(3,2)、红 (0,0)(1,0)(2,0)(3,0)(0,1)(3,1)、中央 4 点空；黑方先行（试玩页比对）。
- [ ] **CC-RULE-03**【P0·手动】走子合法性：仅横竖相邻 1 格到**空位**；越界、落到有子点、斜走、跳步均不在 `legalMoves` 中（试玩页点选验证高亮点）。
- [ ] **CC-RULE-04**【P0·手动】基本吃子：走棋方形成「己方 2 连 + 对方 1 子」恰好 3 子相连 → 吃掉对方 1 子。
- [ ] **CC-RULE-05**【P0·手动】送上门不吃：走入对方 2 连旁形成「对方 2 连 + 己方 1 子」→ 己方子**不**被吃（吃子只由走棋方触发）。
- [ ] **CC-RULE-06**【P0·手动】双线同吃：落点的横线与竖线同时满足 → 一手吃 2 子；两线在同一落子后棋盘状态上判定。
- [ ] **CC-RULE-07**【P1·手动】不吃的形态：交错（己-对-己）不吃；4 子占满一线不吃（须恰好 3 子）；3 子不相连（有空档）不吃；只查落点所在两线——离开的线不结算。
- [ ] **CC-RULE-08**【P1·手动】不连锁：吃子后新形成的吃子形态不再触发第二轮结算。
- [ ] **CC-RULE-09**【P0·手动】终局 eliminated：一方 ≤1 子 → 对方胜，reason=`eliminated`。
- [ ] **CC-RULE-10**【P0·手动】终局 material：连续 20 手无吃子（pass 也计入）→ 子多方胜 reason=`material`；子力相等 → `draw`。
- [ ] **CC-RULE-11**【P1·手动】停一手与 stalemate：一方无合法走法 → 引擎自动 pass（不调用脚本、写入 history `pass:true`）；双方连续互停 → 按子力裁定 reason=`stalemate`（相等 `draw`）。
- [ ] **CC-RULE-12**【P2·代码检视】2000 手安全阀 → `draw`（理论不可达）。

## 二、思考点计量（engine/rules_metered.js）

- [ ] **CC-QUOTA-01**【P0·手动】每手 100 点、仅 `apply` 计 1 点：提交「循环 `apply` 100 次后返回合法走法」的脚本 → 正常；101 次 → 该手抛 quota → 判 `runtime` 负。
- [ ] **CC-QUOTA-02**【P1·手动】其余 API 不计点：`legalMoves`/`judge`/`clone`/`other`/`remaining` 大量调用不耗点。
- [ ] **CC-QUOTA-03**【P0·手动】每手重置：上一手耗尽点数不影响下一手（每手全新 `makeRules(100)` 实例）。
- [ ] **CC-QUOTA-04**【P0·手动】防绕过：交给脚本的 `Rules`/`game.rules` 无 `_reset`/`_rawApply`/`_counts` 属性（脚本内探测返回 undefined）；脚本顶层捕获的 `Rules` 是 0 预算占位——顶层调用 `Rules.apply` 立即抛 quota。
- [ ] **CC-QUOTA-05**【P2·代码检视】引擎自身结算走 `_rawApply` 不占脚本预算；每手实例化杜绝并发对局互相串改预算。
- [ ] **CC-QUOTA-06**【P1·手动】计量边界与文案：只官方当前 Rules 实例的 apply 扣点，自实现内核仍受挂钟限制；指南要求每手用当前 game.rules。留存旧实例可使用旧余额属于尚未关闭边界，不得写成「每手全部推演绝对最多 100 次」。

## 三、沙箱与超时（engine/sandbox.js）

- [ ] **CC-SBX-01**【P0·手动】编译超时：顶层 `while(true){}` 脚本 → 提交时编译失败（2000ms 上限），烟雾 422「编译失败」。
- [ ] **CC-SBX-02**【P0·手动】每手挂钟：`onTurn` 内死循环 → 3000ms 超时 → 判 `runtime` 负（烟雾/挑战/试玩三路径同判）。
- [ ] **CC-SBX-03**【P1·手动】导出形式兼容：`module.exports = function(){}` 与 `exports.onTurn = function(){}` 均可；不导出函数 → 编译失败提示。
- [ ] **CC-SBX-04**【P1·手动】沙箱纯净：脚本内 `typeof require`/`process`/`fs` 均 `undefined`；`Math`/`JSON` 可用（上下文自带，非宿主 realm）。
- [ ] **CC-SBX-05**【P1·手动】异常与非法：脚本 `throw` → `error` 负；返回非法走法（不在 legalMoves、格式错、null）→ `illegal` 负。
- [ ] **CC-SBX-06**【P2·代码检视】每手调用后 `ctx.__me/__opp/__game` 置 null 释放引用。
- [ ] **CC-SBX-07**【P0·自动】getter 返回的合法 from/to 在 VM 内提取，宿主收到普通坐标对象；无限 from getter 被 VM 超时截断 —— `test/engine-security.test.js`。该测试不覆盖所有 Proxy/异常对象形态。
- [ ] **CC-SBX-08**【P0·手动】动作边界：返回自定义坐标迭代器（与数字下标不一致）、Proxy、额外 HTML/循环字段、字符串/小数/越界坐标、缺失 from/to → 仅按规范字段匹配引擎合法项，或本方 illegal/error/runtime 负；不能增子、跳步、把脚本对象写 history 或以 500 逃避结算。必需字段 getter 的执行必须仍受 VM 超时保护。

- [ ] **CC-ENG-05**【P1·手动】`game.board` 为克隆：脚本篡改 board 不影响真实棋局推进。
- [ ] **CC-ENG-06**【P0·自动】正式 history 视图隔离：脚本 push 注入条目或改历史 from[0] → 返回棋谱不受影响 —— `test/engine-security.test.js`。其它嵌套 captured/to 变异见 CC-PLAY-10 手动扩展。
