# 囚徒困境（prisoner）回归测试清单 v1.0

> 范围：`games/prisoner/`（manifest / 服务端适配 / engine / guide / 前端插件）及其在 `/builtin-bots.js` 中的打包段。
> 规则依据：[囚徒困境策划案_v1.0](../GameDesign/囚徒困境策划案_v1.0.md)。平台通用能力见 [平台回归测试清单](平台回归测试清单_v1.0.md)，此处只列囚徒专属与形态差异。
> 使用约定见 [README](README.md)。

---

## 一、规则核心（engine/rules.js）

- [ ] **PD-RULE-01**【P0·手动】收益矩阵：CC=3/3、CD=0/5、DC=5/0、DD=1/1（试玩页逐回合比对得分增量）。
- [ ] **PD-RULE-02**【P0·手动】回合数区间：正式挑战 `actualRounds ∈ [900,1100]`；多打几场观察分布落在区间内（由 seed 的独立 len 流均匀抽样）。
- [ ] **PD-RULE-03**【P0·手动】总回合数对 Bot 隐藏：探针脚本断言 `game` 仅有 `roundNumber` 与 `random`，无 `totalRounds`/`remaining`；对人类透明（规则页/指南/回放页标注区间）。
- [ ] **PD-RULE-04**【P1·手动】返回值归一化：`'C'`/`'D'`/`'c'`/`' C '`/`'cooperate'`/`'coop'`/`'defect'`/`'d'` 均接受；`'x'`/`1`/`null`/对象 → illegal 判负。

## 二、对局引擎（engine/engine.js）

- [ ] **PD-ENG-01**【P0·手动】同时出手语义：双方在同一回合都看不到对方本回合选择（`me/opponent.history` 只含已完成回合；写探针脚本断言 history 长度 = roundNumber−1）。
- [ ] **PD-ENG-02**【P0·手动】入参契约：`me/opponent = {score, history[]}`（history 为 frozen 浅拷贝——脚本 push 抛错或无效，不影响后续回合）。
- [ ] **PD-ENG-03**【P0·手动】三条独立随机流：长度抽样 / a 的 random / b 的 random 互不串扰——a 狂调 `game.random()` 不改变 b 的序列与回合总数。
- [ ] **PD-ENG-04**【P0·手动】失败判定：illegal（非法返回值）/ runtime（单回合超 50ms）/ error（抛异常）→ 当场终局、失败方判负；`failure = {side, kind, round, message}`；**history 长度 = 失败回合之前完成的回合数**（失败回合不入 history）。
- [ ] **PD-ENG-05**【P2·代码检视】整场挂钟 5000ms：超时按「先手序」归咎 a 判 runtime。
- [ ] **PD-ENG-06**【P1·手动】结果判定：总分高者胜；相等 `draw`；`reason='completed'`。

## 三、沙箱与超时（engine/sandbox.js）

- [ ] **PD-SBX-01**【P0·手动】每回合挂钟 50ms：`onRound` 内忙等 >50ms → runtime 判负（错误信息「挂钟超时（onRound 超过 50ms）」）。
- [ ] **PD-SBX-02**【P1·手动】编译超时 2000ms；导出形式 `module.exports = fn` / `exports.onRound = fn` 均可；不导出函数 → 编译失败。
- [ ] **PD-SBX-03**【P1·手动】沙箱纯净：`require`/`process`/`fs` 均 undefined；无思考点计量（与钳王差异——不存在 `Rules`）。

## 四、烟雾测试（engine/smoke.js）

- [ ] **PD-SMK-01**【P0·手动】计划矩阵：老好人(AllC)/冷面人(AllD)/抛硬币(Random50) × a/b 身份 = 6 场，固定种子 11001/11002/22001/22002/33001/33002；同代码重复提交结果一致。
- [ ] **PD-SMK-02**【P0·手动】只拦崩溃不拦输：`always D` 或 `always C` 的弱脚本 → 通过；会超时/抛异常/返回非法值的脚本 → 失败且 failures 指明对手/身份/seed/reason/round。
- [ ] **PD-SMK-03**【P1·手动】失败归因：仅用户方（`failure.side === plan.userIs`）失败才拦；训练囚徒侧异常不冤枉用户。

## 五、赛制与结算（server.js · 单场制）

- [ ] **PD-BATTLE-01**【P0·自动】单场主链路：挑战 → 900–1100 回合 → 总分定胜负 → RP 结算 —— `test/api.e2e.test.js`。
- [ ] **PD-BATTLE-02**【P0·手动】body 字段 `targetPrisonerId`；响应含 `matchUrlId/result/reason/actualRounds/chScore/cdScore/rpChange{…,delta}/scored/failure/scoringNote`。
- [ ] **PD-BATTLE-03**【P1·手动】对手脚本中途失败的挑战：构造必失败对手（如第 N 回合抛异常）→ result 归对方、reason 为失败类型、响应带 failure 明细、正常计分。
- [ ] **PD-DB-01**【P0·手动】落库形态：单行 `battles`——`ext` JSON 为 `{actualRounds, failure}`、`blob` 为选择序列、ch_score/cd_score、seed、双方版本与哈希；**无游戏私有表**。

## 六、blob 选择序列编解码（server.js）

- [ ] **PD-BLOB-01**【P0·手动】编码格式：每回合 2 bit（高位=a、低位=b；C=0、D=1）、每字节 4 回合、高位在前——直连 DB 取 blob 手工解 2–3 个回合与回放比对。
- [ ] **PD-BLOB-02**【P0·手动】解码按真实回合数：completed 场按 `actualRounds` 解；**中途判负场按 `failure.round − 1` 解**——回放绝不出现「blob 尾部未写入字节被解成假 CC」（历史 bug 回归点：构造第 3 回合判负的对局，回放 moves 长度恰为 2）。
- [ ] **PD-BLOB-03**【P2·代码检视】解码防御性夹取：解码长度 ≤ blob 容量（`u.length*4`），畸形数据不越界。
- [ ] **PD-BLOB-04**【P1·自动】迁移保留：旧库 `move_blob` 迁移后回放解码正确 —— `test/migration.e2e.test.js`。

## 七、Agent 数据接口（囚徒形态：按「场」列）

- [ ] **PD-AGT-01**【P1·手动】`GET /api/agent/prisoner/matches` → 按场列 battles（视角视图含 myScore/oppScore/actualRounds/rpDelta/scored）。
- [ ] **PD-AGT-02**【P1·手动】`GET /api/agent/prisoner-opponents/:id/matches` → 侦察摘要（双方得分、codeHash、actualRounds）；目标不存在 404。
- [ ] **PD-AGT-03**【P0·手动】`GET /api/match/prisoner/:urlId` → `match{…, moves[]}`，moves 长度 = 真实进行回合数；不存在 404。

## 八、试玩（单回合推进形态 · extraRoutes + play-one 任务）

- [ ] **PD-PLAY-01**【P1·手动】`GET /api/prisoner/meta` → `{minRounds:900, maxRounds:1100, scoredLimit:10}`；`GET /api/prisoner/opponents` → 3 名训练囚徒（含 summary）+ 榜单前 20 已发布玩家。
- [ ] **PD-PLAY-02**【P0·手动】单回合推进：`POST /api/prisoner/play {opponent, history, myMove}` → 返回双方选择/本回合得分/累计分/roundNumber；服务端按 history 重算累计分（不信任客户端分数）。
- [ ] **PD-PLAY-03**【P1·手动】入参校验：myMove 非 C/D → 400；history 第 i 项非法 → 400 定位「第 i 项」；history >100000 → 400；opponent 缺失/未知训练 id → 400；玩家囚徒不存在 404、未发布 422。
- [ ] **PD-PLAY-04**【P0·手动】信任分流：训练囚徒在**主进程**跑（Network 快、无池占用）；玩家囚徒经执行池 `play-one`（限额 5s）——填满池时后者 503、前者不受影响。
- [ ] **PD-PLAY-05**【P1·手动】玩家囚徒脚本失败（超时/非法/异常）→ 响应 `{over:true, botFailure}`：前端提示、**不判负不计分**、本回合不推进。
- [ ] **PD-PLAY-06**【P1·手动】频控 600/min/IP（高于其它游戏——单回合交互频繁）。
- [ ] **PD-PLAY-07**【P1·手动】试玩不入库：狂玩后 battles 无新增、RP 不变。
- [ ] **PD-PLAY-08**【P2·手动】play-one 视角正确：bot 收到的 `me.history` 是 bot 自己的历史、`opponent.history` 是玩家的（不颠倒——用 TitForTat 类脚本验证其复读的是玩家上一手）。
