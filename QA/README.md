## 使用约定

**条目格式**：`编号【优先级·执行方式】标题：操作 → 期望`

- **编号前缀**：`PF`=平台、`CC`=钳王争霸、`PD`=囚徒困境、`DQ`=象棋暗战。
- **优先级**：
  - 【P0】每次发布前必测（核心链路、计分正确性、安全边界）；
  - 【P1】相关模块有改动时必测；
  - 【P2】边缘场景 / 低风险，重大重构或专项排查时测。
- **执行方式**：
  - 「自动」：条目标注现有测试文件，全绿仅证明该条明确标出的断言范围；缺覆盖或不同路径不能推定通过；
  - 「自动+手动」：自动子项通过后，仍须执行并记录手动部分，整项才能勾选；
  - 「手动」/「代码检视」：需本地脚本、curl、浏览器或读码验收；标注「当前失败/待修复」的条目记录目标行为，不能把缺陷现状当作期望。

**回归跑法建议**：

1. `npm test`（全部自动化：单元 + e2e + 迁移，约 1–3 分钟）+ `npm run test:rules`（钳王规则）；
   两棋类安全定向复跑：`node --test --test-concurrency=1 test/engine-security.test.js test/darkchess-regressions.test.js test/darkchess-replay.test.js test/security-assessment.test.js test/rules-examples.test.js`。此命令覆盖四类回归的自动部分，不包含手动动画或生产验收。
2. 按本次改动波及面挑选清单：只动了某游戏 → 跑该游戏清单 + 平台清单的「通用游戏 API」抽查；动了 `platform/` / `db.js` / `server.js` → 平台清单全量 P0 + 三游戏清单 P0；
3. 发布上线前：四份清单的全部 P0 项。

记录执行日期、代码/部署版本、命令或测试账号、实际输出、通过/失败/未测和待办责任人。先关闭已知 P0，再部署完整 games/platform/前端资产并重启核对指南；本地验证与目标环境验证分别记账。线上主动验证仅在既有授权范围内使用测试账号执行。

**测手动项的通用准备**：

```powershell
$env:DB_PATH = "$env:TEMP\qa-test.db"   # 临时库，不污染开发库
node server.js                            # http://localhost:3000
```

准备两个测试账号（互相挑战用），密钥经「我的选手 → 一键复制 Prompt」获取。curl 示例中 `$KEY` 即该密钥、`$G` 为游戏 id。
