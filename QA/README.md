## 使用约定

**条目格式**：`编号【优先级·执行方式】标题：操作 → 期望`

- **编号前缀**：`PF`=平台、`CC`=钳王争霸、`PD`=囚徒困境、`DQ`=象棋暗战。
- **优先级**：
  - 【P0】每次发布前必测（核心链路、计分正确性、安全边界）；
  - 【P1】相关模块有改动时必测；
  - 【P2】边缘场景 / 低风险，重大重构或专项排查时测。
- **执行方式**：
  - 「自动」：已被自动化测试覆盖，条目标注测试文件——跑 `npm test` 全绿即视为通过，无需人工重复；
  - 「手动」：需人工执行（curl / 浏览器 / 构造脚本）。

**回归跑法建议**：

1. `npm test`（全部自动化：单元 + e2e + 迁移，约 1–3 分钟）+ `npm run test:rules`（钳王规则）；
2. 按本次改动波及面挑选清单：只动了某游戏 → 跑该游戏清单 + 平台清单的「通用游戏 API」抽查；动了 `platform/` / `db.js` / `server.js` → 平台清单全量 P0 + 三游戏清单 P0；
3. 发布上线前：四份清单的全部 P0 项。

**测手动项的通用准备**：

```powershell
$env:DB_PATH = "$env:TEMP\qa-test.db"   # 临时库，不污染开发库
node server.js                            # http://localhost:3000
```

准备两个测试账号（互相挑战用），密钥经「我的选手 → 一键复制 Prompt」获取。curl 示例中 `$KEY` 即该密钥、`$G` 为游戏 id。
