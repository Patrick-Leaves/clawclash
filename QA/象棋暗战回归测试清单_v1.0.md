## 一、棋盘与开局（engine/rules_core.js）

- [ ] **DQ-RULE-01**【P0·手动】棋盘 4 行 × 8 列（x:0–7、y:0–3）共 32 格；开局 32 颗棋子随机打乱、背面朝上**摆满全部格子**（试玩页开局无空格、全部为暗子）。
- [ ] **DQ-RULE-02**【P1·手动】兵种构成与等级：每色 将/帅1、士/仕2、象/相2、車2、馬2、炮2、卒/兵5；等级 将7 > 士6 > 象5 > 車4 > 馬3 > 炮2 > 卒1；LABELS 黑红文字正确（将/帅、士/仕、象/相…）。
- [ ] **DQ-RULE-03**【P0·手动】seed 决定性：同一 seed 重新推导出同一初始分布与同一先手座位（试玩重放依赖此性质——刷新页面后继续对局，棋盘不变）。

## 二、翻棋定序阶段（engine/engine.js）

- [ ] **DQ-SEQ-01**【P0·手动】定序规则：双方各翻一颗，若颜色**不同** → 先翻者执其所翻颜色，进入行棋阶段；若颜色**相同** → 继续各翻一颗再比。
- [ ] **DQ-SEQ-02**【P1·手动】定序阶段只能翻棋：`legalActions` 只含 flip（探针脚本断言 phase='determining' 时无 move 动作）；此阶段双方 `me.side` 为 null。
- [ ] **DQ-SEQ-03**【P2·手动】兜底分支：全部 32 格翻完仍未定色（极端同色序列）→ 系统随机分配颜色进入行棋（规则 §5 第 5 条；可用构造性种子或代码检视确认）。
- [ ] **DQ-SEQ-04**【P1·手动】定色后 `colorOf` 映射：座位(a/b) ↔ 颜色(black/red) 对应关系在响应/回放中一致，胜负按座位换算无颠倒。

## 三、行棋与吃子规则（engine/rules_core.js）

- [ ] **DQ-MOVE-01**【P0·手动】行棋三选一：有暗子时可翻棋；已翻开的己方棋子可横竖 1 格移动到空位；符合条件可吃子。
- [ ] **DQ-CAP-01**【P0·手动】基础吃子仅限**已翻开**的相邻敌子：等级高吃低、**等级相同同归于尽**（双方棋子都移除）；暗子不能被基础吃。
- [ ] **DQ-CAP-02**【P0·手动】特例对：**卒/兵可吃帅/将**；**帅/将不能吃卒/兵**（legalMoves 不含该走法、applyMove 抛错）。
- [ ] **DQ-CAP-03**【P0·手动】炮无基础吃：炮与敌子相邻时不能直接吃（只能移动到空位或隔子吃）。
- [ ] **DQ-CAP-04**【P0·手动】炮隔子吃：同行或同列、炮与目标之间**恰好 1 个**棋子作炮架（明暗不限）；0 架或 ≥2 架非法；目标可为明子或**暗子**（吃暗子后公示其身份于 history.captured）。
- [ ] **DQ-CAP-05**【P1·手动】炮隔子吃细节：炮吃炮**不**同归于尽（单向吃，攻击方炮移动到目标格）；明子目标不能是己方；**暗子目标不校验归属——可能误吃己方暗子**（规则特性，非 bug）。
- [ ] **DQ-CAP-06**【P1·手动】不能吃己方明子；等级不足吃高级 → illegal。

## 四、终局裁定（rules_core.judge + engine）

- [ ] **DQ-END-01**【P0·手动】eliminated：一方棋子（含暗子）被吃光 → 对方胜。
- [ ] **DQ-END-02**【P0·手动】noCapture：连续 40 手（单步，双方各计一步；翻棋/移动/pass 均计入，吃子清零）→ 按真实剩余子力裁定，相等判和；含暗子与全明局面各验一次。DQ-END-05 自动回归已通过，本项完整浏览器/目标环境流程仍待验收。
- [ ] **DQ-END-03**【P1·手动】stalemate：双方连续互停（无任何合法动作各 pass 一次）→ 按子力价值裁定；pass 由引擎自动执行、不调用脚本、写入 history `pass:true`。
- [ ] **DQ-END-04**【P2·代码检视】4000 手安全阀 → draw；时间限制按 DQ-ENG-05 分层验收，不把旧共享 15s 阀当作正确的思考计时契约。
- [x] **DQ-END-05**【P0·自动】真实身份裁定与遮罩推演分离：`test/darkchess-regressions.test.js` 通过真实 32 暗子/双方 52 分 ncm=39→null、40→draw/noCapture，真值不平衡及吃光优先；全暗/混合 fogBoard ncm=0/40→null。stepAction 含暗子 40 步/吃光、stepPass 及浏览器 UMD 通过；脚本 helper 对任意含暗子输入仍 null，全明正常判定。2026-10-10 本地代码回归已闭环，不代表生产部署已修复。

## 五、信息遮罩 fog of war（engine.buildView / fogBoard）

- [ ] **DQ-FOG-01**【P0·手动】Bot 视图遮罩：探针脚本断言 `game.board` 中暗子仅为 `{hidden:true}`——无 side/kind/power；明子含完整信息 + label。
- [ ] **DQ-FOG-02**【P0·手动】me/opponent 契约：`{side, remaining, capturedCount(=16−remaining), revealedPieces}`；remaining 按真实存活数（含暗子）、revealedPieces 只列**已翻开**的己方/对方棋子坐标。
- [ ] **DQ-FOG-03**【P0·手动】试玩响应遮罩：`/api/games/darkchess/play` 返回的 board 永远是 fogBoard 视图——**包括 local 双人模式**（抓包确认暗子无身份字段；现实中两人共享暗棋盘，翻开前谁也不知道底下是什么）。
- [ ] **DQ-FOG-04**【P1·手动】训练棋手不越界：训练棋手只经 `game.rules` 公开 API 操作（不 require rules_core）——代码检视 + 行为上不「未卜先知」暗子。
- [ ] **DQ-FOG-05**【P1·手动】公示信息正确进入 history：翻棋记录含 `revealed{x,y,side,kind,power}`、隔子吃暗子记录含被吃子完整身份（captured）——回放据此逐步揭示。
- [ ] **DQ-FOG-06**【P0·自动+手动】正式 history 隔离：push 注入、改 action.at[0] 不影响最终棋谱 —— `test/engine-security.test.js`。手动扩展 action.from/to、captured、revealed 的嵌套修改和数组增删，真实局面/计数/终局不受影响；服务端试玩见 DQ-PLAY-08。
- [ ] **DQ-FOG-07**【P0·自动+手动】脚本 helper 对含暗子输入 judge 返回 null；`test/security-assessment.test.js`、`test/rules-examples.test.js` 使用真实 fogBoard，`test/darkchess-regressions.test.js` 补全暗/混合、ncm=0/40、真值与遮罩分离、全明价值判定。手动验浏览器展示和全明 eliminated；不得把 null 解释为局面已终局或双方必和。真实裁定另见 DQ-END-05。
- [ ] **DQ-FOG-08**【P1·手动】公开损失与推演：定序时 me/opponent 均存在但统计字段为 null；定色后 capturedCount=16−remaining 指己方损失。炮吃暗子在真实 history 公示身份，下一次回调更新统计；masked apply 的 captured 身份可能缺失。每色 52 减去公开损失可算总子力，不能得知每格身份。

## 六、对局引擎与随机性（engine/engine.js）

- [ ] **DQ-ENG-01**【P0·手动】脚本入参契约：`game = {phase, board(遮罩), turnNumber, noCaptureCount, legalActions, history, random, rules{legalMoves,apply,judge,clone,other,pieceValue}}`；动作格式 `{action:'flip',at:[x,y]}` / `{action:'move',from,to}`。
- [ ] **DQ-ENG-02**【P0·自动+手动】随机实例分离：开局 rng、a/b rngOf 是不同对象 —— `test/security-assessment.test.js`；手动比较同 seed 下 a 多调用 random 前后 b 序列与开局/先手不变。当前测试不证明流具备密码学独立性；固定 seed 派生的反推风险另见 PF-SEC-11。
- [ ] **DQ-ENG-03**【P0·手动】判负三态：返回不在 legalActions 中的动作 → illegal；onTurn 超 3000ms 挂钟 → runtime；抛异常 → error——均当场判负、对方胜。
- [ ] **DQ-ENG-04**【P1·手动】step 原语复用一致性：Node playMatch、试玩重放（play_session）、浏览器本地对局三方走同一套 initMatchState/stepPass/stepAction——同一 seed+同一动作序列在三处推出同一局面（抽查浏览器本地对局与服务器重放）。
- [ ] **DQ-ENG-05**【P0·自动+手动】独立扣时：`test/engine-security.test.js` 自动通过默认入口 seed=1、a 2200ms/手、b 1800ms/手，双方各自耗尽 10000ms 才判对应方 runtime 负。慢 a 2600ms/手传入 3000/3000/3000/2200ms VM 限额，getter 在短余额内中止；显式整局阀仅抛 MATCH_TIMEOUT。**代码已修复**；手动走 HTTP challenge/smoke 验父进程余量、末手优先及回收，不再把旧共享 15000ms 阀作为期望。

## 七、沙箱与超时（engine/sandbox.js）

- [ ] **DQ-SBX-01**【P0·手动】编译超时 2000ms、每手挂钟 3000ms；超时 `err.timeout` → runtime 负、其余异常 → error 负。
- [ ] **DQ-SBX-02**【P1·手动】导出形式 `module.exports = fn` / `exports.onTurn = fn` 均可；沙箱内 `require`/`process`/`fs` undefined；无思考点计量（与钳王差异——`game.rules.apply` 不限次数，只受挂钟约束）。
- [ ] **DQ-SBX-03**【P0·自动】flip/move 在 VM 内提取必需字段，宿主返回规范对象 —— `test/engine-security.test.js`；现有例子 x≤1，不覆盖右半盘。
- [ ] **DQ-SBX-04**【P0·手动】规范化异常：getter/Proxy 抛错、无限 getter、自定义坐标迭代器、额外循环/HTML 字段、非法 action/坐标 → 规范化后按引擎合法项执行，或该座位 illegal/error/runtime 负；不得跨盘移动、伪造 history 或返回 500 不结算。getter 仍可能执行，须处于 VM 时限内；钳王 getter 自动测试不替代暗棋验证。
- [x] **DQ-SBX-05**【P0·自动】8 列边界：`test/darkchess-regressions.test.js` 经实际 makeBot 保留 flip `[4,0]`、`[7,3]` 和 move 跨 x=3/4、6/7、7/6；flip/move 起终点 x=8、y=4、负数、小数、字符串拒绝。manifest smoke 六局、challenge 和玩家脚本 play 的最右合法动作通过，响应暗子仍遮罩。2026-10-10 本地修复已验证，HTTP/浏览器整体验收仍按其余条目执行。

## 八、烟雾测试（engine/smoke.js）

- [ ] **DQ-SMK-01**【P0·手动】计划矩阵：随手/贪吃/推演 × 座位 a/b = 6 局，固定种子 10101/10102/20201/20202/30301/30302；以不依赖时钟、相同输入/初始状态的确定性代码验证重复可跑，不保证任意脚本结果一致。
- [ ] **DQ-SMK-02**【P0·手动】只拦崩溃不拦输：「永远选第一个合法动作」的弱脚本 → 通过；会 illegal/超时/抛异常的脚本 → 失败且 failures 指明对手/座位/seed/reason/turn；仅用户方失败才拦。
- [ ] **DQ-SMK-03**【P1·手动】烟雾脚本必须处理定序阶段（phase='determining' 只有 flip）——只会走 move 的脚本在第一手就 illegal，被烟雾拦下并给出明细。
- [ ] **DQ-SMK-04**【P1·手动】加载与生命周期：顶层计数器确认烟雾只加载一次、六局共享状态，正式单局各手共享状态，新请求重载；加载失败/用户方异常才拦，失败不入库不占号。请求等待 worker 顺序六局完成，父时限 150000ms；不保证依赖时钟的脚本重复结果相同，也不验证棋力。

## 十一、试玩（extraRoutes + play_session）

- [ ] **DQ-PLAY-01**【P1·手动】`GET /api/games/darkchess/opponents` → 3 名训练棋手 + 榜单前 20 已发布玩家；`GET …/players/search?q=` 模糊搜索含 playable。

- [ ] **DQ-PLAY-03**【P0·手动】挑战玩家棋手（不可信路径）：脚本在执行池跑（`play` 单请求父时限 30000ms）；目标不存在 404、未发布 422；频控 120/min/IP。
- [ ] **DQ-PLAY-04**【P0·手动】**训练棋手对战 / 双人同屏走浏览器本地**：Network 面板无 `/api/games/darkchess/play` 请求（经 `/darkchess-bots.js` 的同一套 step 原语本地推演，零网络）；服务器 play 接口对 local/training 仍兜底可用（非浏览器客户端）。
- [ ] **DQ-PLAY-05**【P0·手动】重放防作弊：构造非法 history——行动方不符 / 动作非法 / 有合法动作却 pass / 终局后加动作 → 均 400 且定位第 N 手；history >4000 → 400；humanSeat 非 a/b → 400。
- [ ] **DQ-PLAY-06**【P1·手动】机器人在试玩中 illegal/异常 → 人类判胜；试玩不入库不计分（battles/darkchess_matches 无新增、RP 不变）。
- [ ] **DQ-PLAY-07**【P1·手动】信任分流守卫：主进程路径的 `makeBot(){ throw }` 存在（代码检视）——玩家脚本绝不在主进程编译。
- [ ] **DQ-PLAY-08**【P0·手动】服务端试玩 history 隔离与规范执行：先走合法翻棋，再让玩家脚本增删历史、改 action.at/from/to/captured/revealed 嵌套内容、修改 legalActions，返回自定义迭代器动作 → 原请求/真实历史/响应不被污染，执行动作来自引擎合法列表。正常翻棋、炮吃暗子、同归于尽和重放续局仍正确；不能只用正式 history 单元测试代替此项。
- [ ] **DQ-PLAY-09**【P0·手动】试玩超时分类：无限 onTurn/必需字段 getter → 人类胜/runtime，普通 throw → error；单请求父时限 30000ms。跨请求重建不保留整局独立时钟，须与正式路径分别描述；**当前超时 catch 统一 error，分类待修复验收**。
