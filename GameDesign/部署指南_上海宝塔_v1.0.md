# 部署指南：腾讯云上海轻量服务器（宝塔面板）v1.0

> 目标：把本平台完整部署到**腾讯云上海轻量应用服务器**（宝塔 Linux 面板），与香港服务器**完全独立**——
> 独立代码目录、独立 SQLite 数据库、独立 `SESSION_SECRET`，两边账号/数据互不相通。
>
> 适用前提：服务器已安装宝塔面板；本仓库零第三方依赖（无需 `npm install`），要求 Node.js ≥ 22。

## 0. 总体流程与关键认知

```
阶段 1  服务器 + 宝塔初始化（放行端口、装 Node 22）        ← 当天完成
阶段 2  部署应用 + IP:3000 直连验证                        ← 当天完成
阶段 3  安全加固（clawbot 降权 + iptables 禁出站，必做）    ← 当天完成
阶段 4  ICP 备案（并行推进，一般 1–3 周）                  ← 与上面并行
阶段 5  域名 + Nginx 反代 + HTTPS（备案通过后）            ← 备案后当天
阶段 6  上线验证清单                                       ← 备案后当天
```

**备案时间线（重要）**：上海服务器上，**未备案域名无法使用 80/443 端口**（腾讯云接入侧阻断）。因此：

- 阶段 2 用 **`http://服务器公网IP:3000`** 直连验证（临时放行 3000 端口，验证完关闭）；
- 阶段 5 必须等备案通过后才能做（域名才能解析到 80/443）。

**生产模式开关（重要）**：`NODE_ENV=production` 会给会话 Cookie 加 `Secure` 标记 → **明文 HTTP 下浏览器不保存 Cookie、无法登录**。
所以阶段 2（IP:3000 明文测试）期间**不要设** `NODE_ENV`；阶段 5 配好 HTTPS 后再设为 `production`。

## 1. 服务器 + 宝塔初始化

### 1.1 腾讯云控制台放行端口

轻量服务器有两层防火墙：**控制台防火墙**（最外层）+ 系统防火墙（宝塔里配）。两层都要放行：

1. 登录腾讯云控制台 → 轻量应用服务器 → 你的实例 → **防火墙** → 添加规则，放行：
   - `TCP 22`（SSH）、`TCP 8888`（宝塔面板）、`TCP 80`、`TCP 443`
   - `TCP 3000` **仅阶段 2 临时放行，验证完立刻删除**
2. 若实例创建时选择了「宝塔 Linux 面板」镜像，面板已装好；否则在宝塔官网用一行命令安装。

### 1.2 登录服务器、获取宝塔入口

SSH 登录（轻量服务器默认 root 用户）：

```bash
ssh root@<服务器公网IP>
```

获取面板入口信息（面板地址 / 账号 / 密码）：

```bash
sudo bt default
```

浏览器打开面板地址（形如 `http://IP:8888/xxxxxxxx`），登录后：

1. 首次登录按提示**修改面板密码**（强烈建议，公网面板是攻击面）；
2. 软件商店 → 搜索 **「Node.js版本管理器」** → 安装 → 安装 **Node v22 及以上**（v24 亦可，要求 ≥22）；
   装好后点该版本行的 **「设为命令行版本」**（让 `node`/`npm` 能在终端直接使用）。
3. 终端验证 `node -v`。若提示找不到命令：宝塔每个 Node 版本装在独立目录
   `/www/server/nodejs/v<版本>/bin/`，默认不进系统 PATH，手动补上即可：

```bash
ls /www/server/nodejs/                                    # 确认实际目录名（如 v24.20.0）
echo 'export PATH=/www/server/nodejs/v24.20.0/bin:$PATH' >> ~/.bashrc
source ~/.bashrc
node -v   # 应输出 v24.20.0
```

### 1.3 安装 PM2（用刚才的默认 Node）

```bash
npm install -g pm2
pm2 -v    # 验证
```

> 备选：宝塔软件商店的「PM2管理器」也可用，但它自带独立 Node 环境，环境变量管理不如命令行
> `ecosystem.config.js` 直观。本指南以命令行 PM2 为准。

## 2. 部署应用

### 2.1 拉取代码

```bash
mkdir -p /www/wwwroot/clawclash
cd /www/wwwroot/clawclash
git clone https://github.com/Patrick-Leaves/clawclash.git .
```

> 全新克隆 → 空的 `sixchess.db` 自动建表 → 与香港服务器完全独立，账号互不相通（符合预期）。

### 2.2 生成会话密钥（每个服务器独立一个）

```bash
openssl rand -hex 32
```

把输出保存好——这是上海服务器自己的 `SESSION_SECRET`，**与香港的不同**（重启不换密钥的前提）。

### 2.3 创建 `ecosystem.config.js`（PM2 配置，含密钥，勿提交 git）

```bash
cd /www/wwwroot/clawclash
vi ecosystem.config.js
```

内容（替换 `<...>` 占位符）：

```js
module.exports = {
  apps: [{
    name: 'clawclash',
    cwd: '/www/wwwroot/clawclash',
    script: 'server.js',
    instances: 1,
    autorestart: true,
    max_memory_restart: '500M',
    env: {
      PORT: '3000',
      SESSION_SECRET: '<上一步 openssl 生成的 64 位十六进制串>',
      // 阶段 3 安全加固后填入（见 3.1）：
      RUNNER_UID: '<id -u clawbot 的输出>',
      RUNNER_GID: '<id -g clawbot 的输出>',
      // 阶段 5 配好 HTTPS 后补上并重启（见 5.4）：
      // NODE_ENV: 'production',
      // PUBLIC_ORIGIN: 'https://<你的域名>',
    },
  }],
};
```

> `ecosystem.config.js` 含密钥：确保它**不会**被 `git commit`（本仓库 `.gitignore` 未包含该文件名，
> 部署后若在服务器上做 git 操作，先 `git update-index --skip-worktree ecosystem.config.js` 或加进 `.gitignore`）。

### 2.4 启动并设为开机自启

```bash
cd /www/wwwroot/clawclash
pm2 start ecosystem.config.js
pm2 save            # 保存进程列表
pm2 startup         # 会输出一条 sudo 命令，复制执行，注册 systemd 开机自启
pm2 status          # 确认 clawclash 为 online
```

查看启动日志确认无误：

```bash
pm2 logs clawclash --lines 30
# 应看到：Agent 对战平台已启动: http://localhost:3000
```

### 2.5 本机验证

```bash
curl -s http://127.0.0.1:3000/ | head -20   # 应返回首页 HTML
curl -s http://127.0.0.1:3000/api/leaderboard   # 应返回 JSON（空天梯）
```

### 2.6 公网验证（临时，验完关端口）

1. 腾讯云控制台防火墙临时放行 `TCP 3000`；
2. 浏览器访问 `http://<服务器公网IP>:3000/`；
3. 快速验证（详见 §6 清单，挑关键几项）：注册账号 → 登录 → 建 Bot → 提交一份简单脚本过烟雾 → 试玩 → 发起正式挑战 → 天梯可见；
4. **验证完立刻删除 3000 端口放行规则**。此后直至备案完成，公网入口只剩 22 / 8888。

## 3. 安全加固（SECURITY.md 部署侧「必做」，上公网前完成）

> 背景：平台运行玩家提交的不可信 JS。代码层已有子进程隔离 + Node 权限模型，但**权限模型不拦网络出站**，
> 逃逸脚本仍可对外连接（数据外带 / SSRF）。必须用 OS 层把 runner 子进程的出站网络断掉。

### 3.1 创建专用低权限用户 + 降权

```bash
useradd -r -s /usr/sbin/nologin clawbot     # 专用无登录用户
id -u clawbot                               # 记下 uid
id -g clawbot                               # 记下 gid
```

把 uid/gid 填入 `ecosystem.config.js` 的 `RUNNER_UID` / `RUNNER_GID`，重新加载并重启（**必须带文件名 `startOrRestart`，
不能 `pm2 restart clawclash`——按名字重启不会重读配置文件，改的 env 不生效**）：

```bash
cd /www/wwwroot/clawclash
pm2 startOrRestart ecosystem.config.js
pm2 save
pm2 logs clawclash --lines 10               # 确认正常启动（runner 子进程会以 clawbot 身份运行）
```

验证降权生效：

```bash
ps -eo user,pid,cmd | grep runner.js        # runner.js 进程 USER 应为 clawbot
```

> 前置条件说明：主进程须以 root 运行才有权 setuid（本指南 PM2 即 root 跑的，满足）；
> `platform/`、`games/` 为 root 属主、755/644 权限，clawbot 可读（满足）；数据库文件
> `sixchess.db` 由 Node 权限模型按路径白名单拒读（在放行目录之外），与文件属主无关。
> 可选冗余：`chmod 600 /www/wwwroot/clawclash/sixchess.db*`。

### 3.2 iptables 禁掉 clawbot 的对外连接（放行回环）

```bash
iptables -A OUTPUT -m owner --uid-owner clawbot -o lo -j ACCEPT   # 放行回环（IPC/本地）
iptables -A OUTPUT -m owner --uid-owner clawbot -j REJECT         # 丢弃其余对外连接
iptables -L OUTPUT -n --line-numbers                               # 确认两条规则在列
```

**注意**：宝塔「安全 → 系统防火墙」重启/改规则时可能重建 iptables 链、冲掉这两条规则。
**每次动过宝塔防火墙后，重跑上面两条命令**，并顺手再 `ps` 确认一遍。

> 更彻底（可选）：把整个应用放进禁网的网络命名空间/容器（如 Docker + `--network none`），
> 但轻量服务器上容器方案成本高，owner-match 方案已满足 SECURITY.md 的必做项。

### 3.3 兜底开关提醒

- `CHILD_PERMISSION=off` 会关掉 Node 权限模型——**不要设**（除非出现极端不兼容）；
- `RUNNER_POOL_SIZE` 默认 4，2C2G 机器够用；若高峰期 503 增多（排队超限），可调小（2）避免挤占主进程。

## 4. ICP 备案（与阶段 1–3 并行，一般 1–3 周）

1. 腾讯云控制台 → **备案** → 开始备案；
2. 需要：已购域名（建议与香港站不同域名）、本台上海轻量服务器（备案需绑定实例）；
3. 主体：个人或企业均可，按提示提交证件、幕布照（部分省份需要）、核验短信等；
4. 管局审核通常 1–3 周，期间**不要**给该域名解析任何服务器（会触发接入商拦截检查）。

> 合规提示（详见此前讨论）：ICP 备案只是第一步。本平台含账号/对局/天梯，是否被认定为「网络游戏」
> 进而需要版号、个人主体能否经营，建议在正式对外推广前咨询境内合规律师；备案本身不妨碍技术部署先行。

## 5. 域名 + Nginx 反代 + HTTPS（备案通过后）

### 5.1 解析域名

在域名服务商处把域名 A 记录解析到上海服务器公网 IP（备案通过后）。

### 5.2 宝塔添加站点 + 反向代理

1. 宝塔 → 网站 → 添加站点：域名填你的域名，PHP 版本选「纯静态」，提交；
2. 点站点 → **设置 → 反向代理** → 添加反向代理：
   - 目标 URL：`http://127.0.0.1:3000`
   - 发送域名：`$host`
3. 打开站点配置文件（设置 → 配置文件），确认存在这行（平台频控依赖它取真实客户端 IP，SECURITY.md 要求）：

```nginx
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
```

（宝塔默认模板通常已含；若没有则手动加进 `location /` 的 proxy 段，保存后重载 Nginx。）

4. 浏览器访问 `http://<域名>/`，此时应能看到首页（登录态可能因无 HTTPS 而不可用——下一步解决）。

### 5.3 启用 HTTPS

宝塔 → 站点 → 设置 → **SSL** → 选「Let's Encrypt」→ 勾选域名 → 申请，成功后开启「强制 HTTPS」。

### 5.4 切换生产模式

编辑 `ecosystem.config.js` 的 `env`，补上两行：

```js
NODE_ENV: 'production',
PUBLIC_ORIGIN: 'https://<你的域名>',
```

```bash
cd /www/wwwroot/clawclash
pm2 startOrRestart ecosystem.config.js      # 改了 env 必须带文件名重启，pm2 restart clawclash 不会重读配置
pm2 save
pm2 logs clawclash --lines 10
```

> 现在会话 Cookie 带 `Secure`，仅 HTTPS 下工作；HTTP 明文访问会被强制跳转 HTTPS（宝塔已开强制）。
> 如出现「登录后立即掉线」，先检查是否漏了本步的 `NODE_ENV`（生产模式下明文 HTTP 必然掉线）。

## 7. 日常运维

### 7.1 更新代码（生产更新流程）

```bash
cd /www/wwwroot/clawclash
cp sixchess.db sixchess.db-wal sixchess.db-shm /root/backup/   # 先备份三个库文件（README 要求）
git pull origin main
pm2 restart clawclash
pm2 logs clawclash --lines 20   # 确认启动无异常
```

> `ecosystem.config.js` 不在 git 里（或在 skip-worktree 保护下），`git pull` 不会覆盖它。

### 7.2 常见问题速查

| 现象 | 排查 |
|---|---|
| 面板打不开 | 控制台防火墙是否放行 8888 |
| 域名访问被阻断/跳拦截页 | 备案未通过，或域名未解析到本机 |
| 登录后立刻掉线 | 大概率是 HTTPS 没配好却开了 `NODE_ENV=production`（Secure Cookie 特性） |
| 正式挑战 503 | `RUNNER_POOL_SIZE` 排队超限，调小或升级配置 |
| 所有用户共享频控 | Nginx 未配 `X-Forwarded-For` 头（见 5.2 第 3 步） |
| 重启后进程没拉起 | `pm2 startup` 的 sudo 命令是否执行过 |
| runner 不是 clawbot | `RUNNER_UID/GID` 是否填错/漏填；PM2 是否以 root 跑 |

### 7.3 数据备份

- 数据库即 `sixchess.db` + `sixchess.db-wal` + `sixchess.db-shm` 三个文件（`DB_PATH` 未覆盖时在应用根目录）；
- 建议宝塔「计划任务」每日 `cp` 到备份目录，或同步到对象存储（COS）；
- 两边独立部署 = 两边各自备份，互不依赖。
