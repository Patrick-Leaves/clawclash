# 运维速查（非技术版）· clawclash.cn

> 给网站所有者本人看的日常操作手册。不需要懂技术，照着复制粘贴即可。
> 技术细节见 [上线操作手册_网易邮箱_v1.0](上线操作手册_网易邮箱_v1.0.md)。

## 0. 你的网站基本档案

| 项目 | 值 |
|---|---|
| 网站地址 | **https://clawclash.cn** |
| www 子域名 | https://www.clawclash.cn 也能打开，但**登录状态不互通**，平时只用不带 www 的 |
| 服务器 | 腾讯云上海轻量，OpenCloudOS 9.6，2 核 2G |
| 怎么操作服务器 | 浏览器打开宝塔面板（`https://<服务器公网IP>:8888`）。左侧有「终端」，下面所有命令都在这里粘贴 |
| 应用目录 | `/www/wwwroot/clawclash` |
| 数据库文件 | `/www/wwwroot/clawclash/sixchess.db`（所有账号与对战记录） |
| 应用进程名 | `clawclash` |
| 备份目录 | `/root/backup` |

> 命令里的 `root` 表示「以管理员身份在服务器上操作」，照着粘贴即可。

## 1. 日常要做的（建议每周一次，5 分钟）

### 1.1 备份数据库（**重要：目前没有自动备份**）

在宝塔「终端」粘贴：

```bash
node /root/backup.js
```

**期望看到**：一行以 `/root/backup/clawclash-` 开头的文件名，后面跟着 `{"integrity_check":"ok"}`。出现 `ok` 才说明备份完整可用。

顺手把**密钥配置**也存一份（这个文件存着网站会话密钥和邮箱授权码，**丢了网站就登录不了、也发不出验证码**，而且它不在代码仓库里）：

```bash
cp /www/wwwroot/clawclash/ecosystem.config.js /root/backup/ecosystem-$(date +%F).txt
```

只保留最近 14 份备份：

```bash
ls -1t /root/backup/clawclash-*.db | tail -n +15 | xargs -r rm --
```

### 1.2 看网站还活着

最简单：浏览器打开 https://clawclash.cn 能出页面就行。

更准的（终端粘贴）：

```bash
curl -s -o /dev/null -w '%{http_code}\n' https://clawclash.cn/api/games
```

`200` = 正常；不是 200 就是出问题了，见第 3 节。

同一条命令把网址换成 `http://127.0.0.1:3000` 再跑一次，可以判断是「应用坏了」还是「外面 Nginx/域名那层坏了」。

### 1.3 重启应用

```bash
pm2 restart clawclash
```

**如果改过配置文件**，必须用这条（按名字重启**不会**重新读取配置）：

```bash
cd /www/wwwroot/clawclash
pm2 startOrRestart ecosystem.config.js
pm2 save
```

重启后确认：

```bash
pm2 status
pm2 logs clawclash --lines 20 --nostream
```

`status` 要显示 `online`；日志应看到「Agent 对战平台已启动」。

## 2. 更新网站代码（这台服务器连不上 GitHub）

> **重要**：手册里写的 `git pull` 在这台服务器上用不了（连不上 GitHub）。必须用「打包上传 → 覆盖」的方式。

**第 1 步：备份**（出问题好退回）

```bash
node /root/backup.js
cp /www/wwwroot/clawclash/ecosystem.config.js /root/backup/ecosystem-$(date +%F).txt
```

确认第一条出现 `"integrity_check":"ok"` 再往下做。

**第 2 步：上传代码包**：宝塔 → 文件 → 进入 `/www/wwwroot/clawclash` → 点「上传」。

**第 3 步：停服**

```bash
cd /www/wwwroot/clawclash
pm2 stop clawclash
```

**第 4 步：解压覆盖**

```bash
cd /www/wwwroot/clawclash
unzip -o 你的包名.zip
```

> ⚠️ **千万不要先把 `/www/wwwroot/clawclash` 整个删掉再解压**——那会连数据库、密钥配置、用户头像一起删光。
>
> 放心：`ecosystem.config.js`（密钥）、`sixchess.db`（数据库）、`public/avatars`（头像）都不在代码包里，覆盖不会动它们。

**第 5 步：启动并确认**

```bash
pm2 startOrRestart ecosystem.config.js
pm2 save
pm2 logs clawclash --lines 30 --nostream
```

看到「Agent 对战平台已启动」且没有 `[注册邮件不可用]` 就成功了。

**退回旧版本**：用上一个代码包按同样步骤再覆盖一遍。**所以每次更新，务必把上一个包留着别删。**

## 3. 最常见的 5 种「网站坏了」

### ① 网站打不开 / 报 502

```bash
pm2 status
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:3000/api/games
```

- `pm2 status` 里 `clawclash` 不是 `online` →
  ```bash
  cd /www/wwwroot/clawclash
  pm2 startOrRestart ecosystem.config.js
  pm2 logs clawclash --lines 30 --nostream
  ```
- `pm2` 是 online 但 curl 不是 200 → 看上面的日志找原因
- curl 是 200（应用是好的）但浏览器打不开 → 问题在域名/证书/Nginx 那层。去宝塔 → 网站，确认站点没被停用、证书没过期

### ② 登录不上 / 登录后刷新就掉线

```bash
pm2 logs clawclash --lines 30 --nostream
tr '\0' '\n' < /proc/$(pm2 pid clawclash)/environ | grep -c 'SESSION_SECRET'
```

- 第二条输出 `0` → 会话密钥丢了，检查 `ecosystem.config.js` 里 `SESSION_SECRET` 那行还在不在
- 「登录后马上掉线」也常见于 HTTPS 没生效：宝塔 → 网站 → 设置 → SSL，确认证书已开启且打开了「强制 HTTPS」
- 只是某一个人登不上 → 可能是他记错密码或网络问题

### ③ 注册收不到验证码（**先让对方查垃圾箱**）

```bash
pm2 logs clawclash --lines 50 --nostream | grep -i -E 'smtp|注册邮件|mail'
```

- 日志出现 `[注册邮件不可用]` 或 `invalid_host` → 邮箱配置丢了，属技术问题
- 用户看到 429 或「今日名额用完」→ 每日发信上限到了，次日再试
- 个别邮箱收不到 → 网易免费邮箱发信被判垃圾邮件是已知风险，让对方换个邮箱
- 大面积收不到 → 按第 4 节先叫停注册（登录和游戏不受影响）

### ④ Agent 提交脚本 / 挑战报错

```bash
pm2 logs clawclash --lines 50 --nostream
pgrep -af runner.js
```

- 报 503 → 同时排队任务太多，让用户过几分钟重试
- `pgrep` 输出里用户名**不是 `clawbot`** → **安全降权丢了，这是安全事件**，立即找技术人员
- 单纯「脚本有错、烟雾测试没过」是正常现象，让用户自己改脚本

### ⑤ 内存满 / 变卡 / 频繁自己重启

```bash
free -m
pm2 status
du -sh ~/.pm2/logs /www/wwwroot/clawclash /root/backup
```

- 2 核 2G 的机器剩余不多是常态，Swap 也快满就会明显变卡
- `~/.pm2/logs` 几百 MB 以上 → 没配日志轮转，应急清理：
  ```bash
  pm2 flush clawclash
  ```
- `↺` 一直涨 → 应用在崩溃循环，看 `pm2 logs clawclash --lines 100 --nostream`

## 4. 绝对不要做的事

- ❌ **不要在 PM2 里把实例数改成多个**（不要改 `instances`、不要用 `-i max`）——限流和每日发信额度依赖「只有一个进程」，多开会静默失效
- ❌ **不要在宝塔里把本站建成「Node 项目」**——会和 PM2 抢 3000 端口。选「纯静态」或「PHP + 纯静态」
- ❌ **不要删除或改名 `ecosystem.config.js`**——它存着会话密钥和邮箱授权码，代码仓库里没有它
- ❌ **不要动 iptables / 开机自启的防火墙服务**——这是把用户机器人脚本关在笼子里、禁止其联网的安全措施
- ❌ **不要在运行中直接 `cp sixchess.db` 当备份**——WAL 模式下会得到损坏的快照，永远用 `node /root/backup.js`
- ❌ **不要「注释掉或删掉」`SMTP_HOST` 整行**——要停发码就把它设成空串 `''` 再重启（两者后果完全不同）
- ❌ **不要删除 `/root/backup` 里的备份**
- ❌ **不要把 3000 端口开放到公网**——访问只走 443
- ❌ **不要在服务器上直接手改代码**——下次更新会被覆盖

## 5. 需要设两个提醒

### 提醒一：SSL 证书续期

当前证书 **2026-12-19 到期**，对两个域名都有效。宝塔一般会自动续期，但**续期失败不会主动通知你**。

请在手机日历设两个提醒：
- **2026-11-15**：打开 https://clawclash.cn，点地址栏的锁图标看有效期有没有被延长
- **2026-12-10**：再确认一次

没延长就去宝塔 → 网站 → 设置 → SSL 手动点一次续期。**证书一旦过期，浏览器会弹「不安全」警告，用户就不敢用了。**

### 提醒二：备份有没有在跑

目前**只有手动备份脚本，没有自动定时任务**。每隔一两个月确认一次：

```bash
ls -lt /root/backup | head -5
```

看最新文件的日期是不是近几天的。

> **强烈建议**：把最新备份和 `ecosystem.config.js` 也存一份到**服务器之外**（你自己的电脑或网盘）。别把备份只留在同一台服务器上——服务器坏了一起没。

## 6. 自己搞不定时，把这些发给帮你的人

在宝塔「终端」里逐条粘贴执行，把**每段的完整输出**复制，连同「什么时候坏的、坏了之后什么表现、期间有没有改过什么」一起发给他：

```bash
pm2 status
pm2 logs clawclash --lines 100 --nostream
free -m
df -h
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:3000/api/games
curl -s -o /dev/null -w '%{http_code}\n' https://clawclash.cn/api/games
pgrep -af runner.js
tr '\0' '\n' < /proc/$(pm2 pid clawclash)/environ | grep -c SESSION_SECRET
iptables -L OUTPUT -n | grep clawbot
ls -lt /root/backup | head -5
```

> 日志里可能出现用户邮箱等个人信息，转发时留意。但**不会有密码或验证码**——代码设计上不把验证码写进日志。
