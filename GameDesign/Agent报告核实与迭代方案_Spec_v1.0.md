## 一、给作者的一页纸（非技术摘要）

1. **两份报告共 26 条主张。核实后：21 条成立或部分成立，但其中绝大多数是"文档写得不够清楚"，不是程序错误；2 条不成立（报告理解有误）；3 条属于"设计取舍/等数据再定"。**

2. **报告里最吓人的那条数据是错的**：钳王报告中"85% 对局以无吃子结算、平均 82.7 手、200 局全和、先手是劣势"——这些数字要么是**暗棋的数据**（32 颗子的棋盘，钳王只有 12 颗），要么是**同一盘棋本地重复数了 200 遍**（双方是一样的确定性脚本）。不能据此改任何规则。要评估钳王平衡性，得先重新做统计。

3. **核实中发现 5 个两份报告都没写、但真实存在的问题**（其中 2 个严重，均已在本地复现）：
   - **N3【严重·公平】拖时间的人能赢**：比赛总时间用完时，系统判负的是"轮到谁走"而不是"谁耗的时间"。实测：一方每手 2.6 秒、另一方每手 0.005 秒，10 秒一过，**慢的一方获胜、快的一方被判负**。等于给"输棋就拖钟"开了一条赢棋通道。
   - **N4【严重·公平】脚本可以"作弊"绕过走棋规则**：脚本返回的走法会被系统"检查一套、执行另一套"。实测：一步表面合法的相邻走子，实际能让自家棋子凭空多一颗（钳王复现 6→7 颗）；暗棋原语层复现为一颗車横跨全盘吃子。此外脚本还能故意让比赛报错中断——快输时"掀棋盘"避免掉分。
   - **N2【安全】比赛记录可被参赛者篡改，且能注入公开回放页**：脚本能改对局棋谱（会原样入库、原样出现在公开回放页）；钳王回放页把棋谱里的内容**不转义**直接当 HTML 渲染，构造过的棋谱会让**任何打开该回放页的人**在浏览器里执行攻击者写的代码（平台目前也没有 CSP 这类防护）。胜负判定不受影响，但页面安全与记录可信度受影响。
   - **N1【功能】暗棋给脚本用的"胜负判定"工具算错**：脚本调用官方公开的 `game.rules.judge(...)` 时，只要场上还有暗子，它恒定回答"红方已把黑方吃光"。开局第一步就这样回答。
   - **N5【余量】暗棋正式挑战的超时上限偏紧**：最坏情况约 22 秒，上限却是 20 秒，慢脚本有概率被"冤枉掐断"。

4. **建议的处理顺序**：先修 N4、N3、N2（公平与安全）→ 再修 N1、N5（功能与余量）→ 同时出一版**指南修订包**（纯文字，改完立即生效，不影响任何已发布脚本）→ 设计层面的问题（炮打暗子、结算阈值）**等作者拍板**，并且钳王那几条要**先重做统计**再谈。

5. **需要拍板的第一件事**：修 N3 时，思考时间从"双方共享 10 秒"改成"**每方各有一份预算**"。预算给 **10 秒/方**（推荐，对现役脚本只多不少）还是 **7.5 秒/方**（更省服务器资源，但会伤到"单手 1~2 秒"的慢脚本）？详见第六节。

## 三、核实中新发现的问题（两份报告均未提及）

### N1 暗棋：给脚本用的"胜负判定"在遮罩棋盘上给出错误答案 【已复现】

- **现象**：脚本调用官方指南公开的 `game.rules.judge(game.board, ncm)`（`guide.js:53`）时，只要场上还有暗子，输出恒为 `{winner:'red', reason:'eliminated'}`——即"红方已经吃光黑方"。
- **复现输出**（本地，开局局面）：
  ```
  真棋盘 judge → {"winner":"draw","reason":"noCapture"}
  遮罩棋盘 counts → {"black":0,"red":32}
  遮罩棋盘 judge → {"winner":"red","reason":"eliminated"}
  ```
- **根因**：`games/darkchess/engine/rules_core.js:168-176` `counts()` 把 `{hidden:true}` 走 else 分支计成红方；`:178-185` `pieceValueSum()` 读不到 `power` 得 NaN；`:193-196` `judge()` 见 `black===0` 直接判红方吃光获胜。暴露点：`games/darkchess/engine/engine.js:117`（`judge: core.judge`）+ `:108`（传入 fogBoard）。
- **影响**：诚实脚本的自评/终局探测被误导；指南公开的 API 在主玩法上不可用。**引擎真实裁定用的是全真棋盘，胜负结果不受影响**。
- **修复方向（推荐 A）**：遮罩棋盘上 `rules.judge` 语义改为"此刻无法判定"（返回 null），场上已无暗子时按真值返回；文档同步说明。备选 B（本期不做）：另给一个基于公开信息的期望值工具。

### N2 对局记录不可信：脚本可篡改入库回放，并可注入公开回放页 【前半已复现 + 链路静态确定】

- **现象一（可篡改）**：两游戏的 `game.history` 都是把引擎内部数组**按引用**交给脚本（`engine_quota.js:76`；暗棋 `engine.js:112`），脚本可增删改；对局结束后引擎把同一数组返回并原样入库（`games/clawclash/server.js:233-234`；`games/darkchess/server.js:199-203`），公开回放接口据此渲染。
- **现象二（可注入）**：钳王把脚本返回值直接存进 history（`engine_quota.js:95`，直接调用脚本对象上的 `slice()`）；回放页 `moveLiHtml()` 把 `h.from`/`h.to` **不做转义**拼进 innerHTML（`games/clawclash/public/app.js:356-359`，经 `:349-353` 试玩列表与 `:806-814` 回放列表两处渲染）。构造过的内容会让**任何打开该回放页的人**在浏览器中执行攻击者写入的代码；平台目前无 CSP（见另一份安全评估）。暗棋回放页已用 `esc()` 转义（`games/darkchess/public/app.js:478`、`:744`），风险较低。
- **现象三（数据量）**：脚本可向 history 塞入任意大小内容，入库、出库、页面渲染均被撑大。
- **影响**：公开回放页的内容安全与记录可信度；胜负判定不受影响（判定发生在篡改之前）。
- **修复方向（建议全做）**：
  1. 引擎写 history 时只写引擎自己的值（与 N4 修复共用"改用引擎匹配到的动作对象"）；
  2. 传给脚本的 `game.history` 改为**冻结快照**：history 条目在创建时冻结，每手传给脚本的是 `Object.freeze(history.slice())`（O(n) 的小拷贝）——脚本改不动引擎的记录；
  3. 前端转义：钳王 `moveLiHtml` 的 `from/to/captured` 一律用已有的 `esc()` 包裹（壳层已提供），并对畸形条目做"跳过不渲染"的防御；
  4. 回放接口加字段类型校验（from/to 必须是长度 2 的数字数组），非法条目丢弃并标注。
- **兼容性**：正常棋谱渲染不变；**旧数据无需清洗**（转义后无害）。

### N3 整场挂钟判负方向错误：拖时间的一方能赢 【已复现】

- **现象**：整场挂钟上限（钳王 10 秒 `engine_quota.js:48`；暗棋 15 秒 `engine.js:190`）在"每轮开始时"检查，而这时行棋权已经交给了对方 → 判负的是**没有拖时间的一方**。
- **复现**（钳王引擎，本地）：一方每手 2.6 秒（低于每手 3 秒上限），另一方每手 0.005 秒。
  ```
  {"winner":"black","reason":"runtime","turns":7,"elapsedMs":10415}
  ```
  黑方把共享的 10 秒耗完（第 4 手结束于 10.4 秒），红方被判 runtime 负、黑方获胜。线上同构（暗棋 `engine.js:190`）。
- **影响**：直接影响天梯公平——输棋方可以"每手合法但慢"把对手拖成判负；同时报告 1.5/2.4 的挂钟叙述需按修复后语义重写。
- **修复方向（推荐）**：
  1. **每方独立时钟**：每方每局一份思考预算（默认 10 秒/方，见第六节决策项）。每手开始前：本方剩余 ≤ 0 → 该方判 runtime 负；`onTurn` 返回后扣减本方用时并判定；每手 vm 超时从固定 3 秒收紧为 `min(3 秒, 本方剩余)` ——拖钟在机制上不可行；
  2. 保留一个整体安全阀（如 2 倍总预算）纯作防御；
  3. 随实现调整 manifest 上限（`games/clawclash/index.js:47-51`、`games/darkchess/index.js:50-54`）：钳王 challenge 40000→**60000**ms（修复后最坏约 44 秒）；暗棋 challenge 20000→**30000**ms（最坏约 25 秒，顺带解决 N5）；两个 smoke 维持 90000（最坏约 61 秒）。
- **兼容性**：对"自己慢、对手快"的现役脚本只多不少（今天共享 10 秒，改后每方各自 10 秒）；"靠拖钟取胜"的路径被移除。

### N4 脚本返回值"校验一套、执行另一套"，并可让比赛中断 【已复现】

- **现象一（瞬移/凭空加子）**：引擎校验读脚本动作的**下标**、执行时却把同一对象当**可迭代对象**再读一遍坐标：
  - 钳王：校验 `engine_quota.js:87-90`（下标）与执行 `rules_core.js:66`（解构/迭代器）；`_rawApply` 完全不做合法性校验。本地复现：一次看似合法的相邻走子后，黑方子数 6→**7**（凭空多一子）。
  - 暗棋：校验 `engine.js:31-32`、`:207-210`（下标）与执行 `rules_core.js:115`（解构）、`:121`（`isAdjacent` 用下标）。本地原语级复现：(0,0) 的車执行"一步相邻走子"，实际横跨全盘吃掉 (7,3) 的卒并落位。
- **现象二（异常中止比赛）**：校验与执行都在 try/catch 之外（`engine_quota.js:87-92`；暗棋 `engine.js:207-210`）。脚本返回带陷阱的对象可让任务抛错 → 挑战接口返回 500"对战执行失败"且**不结算**（`games/clawclash/server.js:187-188`）——快输的一方可以用"掀棋盘"避免掉分；脚本还能借 Getter 在 vm 超时保护之外执行任意长逻辑，把 worker 拖到硬超时被杀。
- **影响**：胜负可被直接操纵（凭空增子影响按子数的判定）；"中止"路径破坏计分一致性；worker 资源可被恶意消耗。
- **修复方向（三层，建议全做）**：
  1. **沙箱层净化**（`games/*/engine/sandbox.js` `makeBot`）：`onTurn` 返回后，在 vm 内**带超时**做一次 JSON 序列化快照（超时/失败/超长按 illegal 处理），跨边界只传纯数据——Getter/Proxy 拿不到执行机会；
  2. **引擎层归一**：校验通过后，从引擎自己生成的合法动作列表里取出**匹配项**，用引擎自己的对象执行并写 history，不再触碰脚本对象（两游戏 + 钳王 `play_session.js` 同步改）；
  3. **异常兜底**：校验+执行整体包进 try/catch，异常判定为**该方** illegal/error 负（替代 500 中止）。
- **兼容性**：正常脚本（返回普通 `{from,to}` / `{action,...}` 对象）行为不变；返回带额外字段的对象仍可用（快照保留字段）。

### N5 超时余量表偏紧 【静态推算】

- 暗棋 challenge：限 20000ms；最坏 ≈ 2 次编译（各 ≤2 秒，`sandbox.js:13`）+ 单局 15 秒（`engine.js:185`）+ 末手超出（≤3 秒）≈ **22 秒 > 20 秒**。
- 烟雾（两游戏）：限 90000ms；理论上暗棋最坏 ≈ 6 × (15+3) ≈ 108 秒（钳王 ≈ 78 秒，在限内）。烟雾对手是内置快棋手，实际跑不满 → 低优先级。
- **修复**：随 N3"每方时钟 + vm 超时收紧"一并重推最坏值（见 N3 第 3 条数值）；N5 不再是独立改动。
