## 一、指南现行契约

| 项目 | 钳王争霸 | 象棋暗战 |
|---|---|---|
| 棋盘 | 4×4，`board[x][y]`，x/y 均为 0–3 | 8 列×4 行，`board[x][y]`，x=0–7、y=0–3 |
| 合法动作 | `game.legalMoves`，返回 `{from:[x,y],to:[x,y]}` | `game.legalActions`，返回 `{action:'flip',at:[x,y]}` 或 `{action:'move',from,to}`；定序阶段只有 flip |
| 归属与损失数 | `capturedCount = 6 - me.pieces.length`，指己方损失 | 定序时双方对象仍存在，但 side/remaining/capturedCount/revealedPieces 均为 null；定色后 `capturedCount = 16 - remaining`，remaining 含暗子 |
| 无吃子计数 | `noCaptureMoves`，20 个单步 | `noCaptureCount`，40 个单步 |
| pass | 无合法动作时自动执行，不调用脚本；计入无吃子计数和 history | 同左；双方连续 pass 才触发僵局，不要求对方同时无动作才能单方 pass |
| 思考点 | 每手提供新的 100 点 Rules 实例，仅该实例的 `apply` 扣点 | 无思考点配额 |
| 正式赛制 | 一次挑战两局，交换黑/红，合计结算一次 | 一次挑战一局，按 a/b 座位换算挑战者视角 |

发生吃子立即清零无吃子计数。「场」始终指一次挑战：哈希对前 10 场计分，钳王两局只消耗一次资格。反刷分参数、开局和结算阈值未调整。

钳王吃子只检查**本手落点的横竖两线**：恰好三子相连时，按本手执方定义「己」，`己-己-敌` 或 `敌-己-己` 才吃敌子；与先前由谁摆成无关。离开的线不结算。

暗棋炮隔一子可打暗子，**不校验暗子归属，可能吃掉己方暗子**；明子目标仍须是敌方。真实吃子后公开身份写入 history，下一次回调的 remaining/capturedCount 才反映更新。遮罩推演中吃暗子的 captured 身份字段可能为 undefined。每色初始子力为 52，减去公开 captured 的 power 可推导剩余总子力，不能据此知道每格暗子身份。

暗棋 `game.rules.legalMoves` 不包含翻棋，`apply` 不模拟翻棋；完整动作以 legalActions 为准。Agent 的 `game.rules.judge` 对含暗子的输入返回 null（无法判定），全明局面按规则判定。规则核心 `core.judge` 仅在棋子归属或价值信息不完整时返回 null；带完整身份的真实暗子正常计入吃光和 40 单步终局裁定。

### 代码生命周期、烟雾和侦察

- 一个 smoke 任务只编译用户代码一次，三名训练手 × 两个执方/座位共六局，在同一 worker 顺序执行，请求等待完成；顶层状态跨六局保留。
- 一次钳王 challenge 两方各编译一次，两局复用各自代码实例；暗棋 challenge 只有一局。新挑战、新提交和玩家脚本试玩请求会重新加载，记忆不跨请求保留；跨局记忆需自行初始化。
- 加载失败，或任一局用户方因 illegal/runtime/error 判负，才阻止发布；普通输棋/和棋、训练手方异常不据此判用户失败。失败不入库、不占版本号。通过仅说明这些场景的运行可靠性。
- 固定烟雾种子用于复跑，不保证依赖时钟、外部状态或随机实现的脚本永远产生同一结果。
- 正式挑战使用新种子。钳王布局固定；双方不依赖随机、时钟或跨局状态且初始内部状态相同时，可逐手复现。暗棋种子还影响布局和先手，不能仅凭同一对手保证复现。
- 侦察与反侦察依赖实际策略；只改代码哈希不保证棋路变化。
- 指南在 manifest 加载时构造 `guideMarkdown`；修改 `guide.js` 后需重新加载服务并核对指南端点，线上是否生效需独立验证。

## 二、动作与历史边界

两游戏 sandbox 在**同一次受单手时限保护的 VM 调用中**执行 onTurn 并提取必需动作字段；正式对局时限取 3000ms 与本方剩余预算的较小值，VM 整数毫秒最低为 1ms。坐标需为整数数组，暗棋 x 上界复用 WIDTH=8、y 上界复用 HEIGHT=4。宿主重新构造普通对象，引擎匹配自己的合法列表，使用匹配项执行和写记录，额外返回字段不参与执行或入库。getter 在规范化时仍可能执行；无限 getter 受同一 VM 时限控制，不能写成「getter 永不执行」。这不是 Node vm 的 RCE 隔离保证。

正式对局与服务端试玩都为脚本构造深层隔离的 history 视图，保护嵌套 action、坐标、captured、revealed；脚本修改该视图不会改真实记录。执行结果和试玩响应也复制历史。记录格式：

```text
钳王：{turn, side, from:[x,y]|null, to:[x,y]|null, captured:[[x,y],...], pass}
暗棋：{turn, seat, action:{action:'flip',at}|{action:'move',from,to}|null,
       captured:[{x,y,side,kind,power},...], revealed:{x,y,side,kind,power}|null, pass}
```

turn 从 1 起按单步计，暗棋 seat 为 a/b；pass 时动作/坐标为 null，captured 为 []，revealed 为 null。正式对局安全步数上限为钳王 2000、暗棋 4000。客户端试玩历史由规则重放校验，采用引擎自有合法动作，不信任附带吃子/翻子结果。

## 三、时间口径及未闭环部分

| 层次 | 钳王争霸 | 象棋暗战 |
|---|---|---|
| 编译顶层执行 | 2000ms | 2000ms |
| 单次 onTurn + 动作规范化 | 至多 3000ms，正式对局不超过本方剩余预算（VM 最低 1ms） | 同左 |
| 独立思考时钟（已实现） | 每局 black/red 各 10000ms | 每局 a/b 各 10000ms |
| 引擎整局安全阀 | 默认 Infinity；显式 maxMatchMs 触发时抛 MATCH_TIMEOUT，不判某方负 | 同左 |
| 父进程 smoke 硬时限 | 150000ms | 150000ms |
| 父进程 challenge 硬时限 | 60000ms，两局合计 | 30000ms，一局 |
| 父进程 play 硬时限 | 30000ms，单请求 | 30000ms，单请求 |

独立时钟按每次 bot 调用前后的时间差扣本方余额，余额 ≤0 时本方 runtime 负；pass 不调用脚本。父进程时限覆盖编译、对局、返回等任务执行，不包含排队等待。

**默认共享阀冲突与单手余量已修复**：正式 manifest 仍调用默认引擎入口，但不再启用旧 10/15 秒共享判负阈值；父进程负责整个任务的硬时限。显式传入整局上限时只中止任务，不产生玩家胜负。新增默认入口双方慢棋、独立余额扣减、剩余预算传给 VM、无限 getter 短时限测试。试玩不保留跨请求的每方整局时钟，其超时异常目前仍归为 error（CC-PLAY-11 / DQ-PLAY-09）；这些独立待办未纳入本次四类修复。

## 四、公共回放契约

两游戏 `matchDetail` 显式构造 DTO，不再展开数据库整行；辅助函数位于 `platform/public_replay.js`。公开详情不含 seed、内部数字主键、battle_id、双方 code hash/version、原始 game_json/initial_layout。侦察摘要接口仍有 codeHash，这是另一契约，不代表所有公开接口都去掉了哈希。

| 响应 | 保留字段 |
|---|---|
| 钳王详情 | ok、matchUrlId、winner、reason、turns、finalChallengerPieces、finalChallengedPieces、challengerSide、gameNo、gameData、双方 Name/Avatar |
| 钳王 gameData | initialBoard（固定布局）、history（规范棋谱字段） |
| 暗棋详情 | ok、matchUrlId、winner、reason、turns、initialBoard、gameData、双方 Name/Avatar |
| 暗棋 initialBoard | 暗子仅 `{hidden:true}`；明子保留 hidden/side/kind/power；空格 null |
| 暗棋 gameData | history；翻棋从 revealed 揭示、炮击暗子从 captured 公示，结束时仍未揭示的格子继续隐藏 |

正式挑战执行结束后才落库，没有单独的进行中棋谱记录；未知/尚未落库的 urlId 返回 404。此结论是本地代码证据，生产版本需独立核对。暗棋试玩为无状态续局仍回传 seed，这是试玩现行设计，不能宣称 seed 已从全部端点移除或具有抵抗客户端重建开局的能力。

钳王坐标文本新增 HTML 转义；暗棋既有文本转义保留。暗棋帧重建使用遮罩开局与逐手公示字段，先清掉 captured，再在攻击子未被记录为吃掉时落位；普通吃子、卒吃将、炮吃明/暗子保留攻击方，同等级基础吃子移除双方。完整畸形记录校验仍待完成。公共 DTO 脱敏、HTML 转义、正常帧重建与完整回放校验是不同验收项。
